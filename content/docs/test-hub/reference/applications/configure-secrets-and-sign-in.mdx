title: Configure secrets and sign-in
description: Give tests access without putting credentials in prompts or scenario files.
icon: key-round
---

Use a dedicated account for tests that require sign-in. Give it the permissions each test needs, and keep its credentials available for future runs.

## Choose how the test account signs in

The application's **Credentials** wizard stage offers two methods:

| Method | Values requested |
| --- | --- |
| **Password** | Username and password. |
| **OTP** | Mobile number and, optionally, a fixed OTP code. |

Choose **Skip for now** if the application needs no sign-in or if you will add test access after registration. For different roles, use separate test accounts; an agent account cannot stand in for a manager account when the scenario checks manager-only access.

Credentials are optional. If you enter them in the wizard, Test Hub creates and links the corresponding secret keys when you finish setting up the application. You do not need to add the same values again on the **Secret Keys** tab.

## Verify the account

Run a short sign-in scenario before relying on credentials in a larger suite. Check that the runner can reach the target, sign in, and see the intended role or page. For session-cookie applications, later authenticated steps must use the signed-in session.
