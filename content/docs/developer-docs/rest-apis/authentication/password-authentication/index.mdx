## Password Authentication

This section covers the password-based authentication APIs available in SolidX.

<Callout type="info" title="Mental Model">

Password authentication establishes a SolidX session from user credentials and then keeps that session active through access and refresh tokens.

- Registration creates the user account when public registration is enabled.
- Authentication exchanges credentials for tokens.
- Refresh, password reset, user info, and logout manage the lifecycle of that session.

</Callout>

In a password-based flow, your application collects the user's email or username and password, then sends them to `POST /api/iam/authenticate`. If the credentials are valid, SolidX IAM returns two tokens:

- `accessToken`: Send this with each protected API request in the `Authorization: Bearer <ACCESS_TOKEN>` header.
- `refreshToken`: Use this only to request a new access token when the current one expires. Treat it as a long-lived secret. SolidX returns both tokens in the JSON response body. Store the refresh token as a sensitive credential, not as regular client-side application state.

When a protected REST API receives the bearer token, SolidX validates it, identifies the user, loads the user's roles, and makes that authenticated context available to the API request.

## Implementation Overview

SolidX provides a comprehensive password-based authentication mechanism with the following endpoints:

1. **Register**
2. **Authenticate**
3. **Refresh Tokens**
4. **Forgot Password**
5. **Change Password**
6. **Get User Info**
7. **Logout**

<Callout type="info" title="Token Lifecycle">

The authenticate endpoint returns access and refresh tokens. Use the access token for protected API calls, and use the refresh token when the access token expires.

</Callout>

## 1. Register

Allows users to create a new account.

### Endpoint

```http
POST /api/iam/register
```

### Environment Variables

- `IAM_ALLOW_PUBLIC_REGISTRATION`: Allows public registration when set to `true`.

<Tabs defaultValue="request">
  <TabItem value="request" label="Request">

  ### Headers

  ```http
  Content-Type: application/json
  ```

  ### Request Body

  ```json
  {
    "fullName": "string",
    "username": "string",
    "email": "[EMAIL]",
    "password": "[PASSWORD]",
    "mobile": "string",
    "roles": ["string"]
  }
  ```

  </TabItem>
  <TabItem value="response" label="Response">

  ### Response Body

  ```json
  {
    "fullName": "string",
    "username": "string",
    "email": "[EMAIL]",
    "mobile": "string",
    "forcePasswordChange": true,
    "roles": [...],
    "id": 0,
    "createdAt": "...",
    "updatedAt": "..."
  }
  ```

  </TabItem>
</Tabs>

<Callout type="warning" title="Response Note">

The response body can be optimized. It currently includes sensitive data like passwords.

</Callout>

## 2. Authenticate

Log in and receive access and refresh tokens.

### Endpoint

```http
POST /api/iam/authenticate
```

### Environment Variables

- `IAM_JWT_ACCESS_TOKEN_TTL`: TTL for access tokens (default: 60 mins).
- `IAM_JWT_REFRESH_TOKEN_TTL`: TTL for refresh tokens (default: 1 day).

<Tabs defaultValue="request">
  <TabItem value="request" label="Request">

  ### Headers

  ```http
  Content-Type: application/json
  ```

  ### Request Body

  ```json
  {
    "email": "[EMAIL]",
    "username": "",
    "password": "[PASSWORD]"
  }
  ```

  </TabItem>
  <TabItem value="response" label="Response">

  ### Response Body

  ```json
  {
    "data": {
      "user": {
        "email": "[EMAIL]",
        "username": "[EMAIL]",
        "roles": ["Admin", "Internal User"]
      },
      "accessToken": "<ACCESS_TOKEN>",
      "refreshToken": "<REFRESH_TOKEN>"
    }
  }
  ```

  </TabItem>
</Tabs>

Initiates and confirms password reset flow.

Starts the password reset process and sends a reset token to the user.

### Endpoint

```http

```

## 7. Logout

Invalidate the current session.

### Endpoint

```http
POST /api/iam/logout
```

<Tabs defaultValue="request">
  <TabItem value="request" label="Request">

  ### Headers

  ```http
  Content-Type: application/json
  ```

  ### Request Body

  ```json
  {
    "refreshToken": "<REFRESH_TOKEN>",
    "allDevices": false
  }
  ```

  `refreshToken` is required. Set `allDevices` to `true` to revoke refresh tokens for every device belonging to the user. Omit it or set it to `false` to sign out only the session that issued this refresh token.

  </TabItem>
  <TabItem value="response" label="Response">

  ### Response Body

  ```json
  {
    "message": "Logged out successfully"
  }
  ```

  </TabItem>
</Tabs>

## What Happens After Login?

After successful password authentication, the client receives an access token and refresh token in the JSON response. Use the access token in the `Authorization: Bearer <ACCESS_TOKEN>` header for protected APIs. Use the refresh token only with the refresh endpoint, and store it as a sensitive credential rather than regular client-side state.
